# CVAE β Sweep — Methodology Reference

Methods reference for the CVAE β (KL weight) tuning investigation, written for
transcription into the paper's Methods section — mirrors
docs/mil_tiers_methodology.md's convention: **this file is methodology only, no
headline numbers or conclusions.** Results live alongside the generated artifacts in
`results/suite600_beta_sweep/` (plots) and this doc's companion findings writeup
(not yet consolidated into its own file at time of writing — see §7). Update this
file when a method changes; record numbers elsewhere.

Code: `src/models/cvae.py`, `src/models/losses.py`, `pipeline/cvae_stage.py`
(`_train_one_fold`, `run_local`), `pipeline/modal_cvae.py` (`run_on_modal`,
resume-checkpoint upload/download), `pipeline/run_suite.py`. Diagnostics:
`scripts/plot_beta_sensitivity_combined.py`; the per-sweep loss-curve plots and the
`compute_synth_std_ratio.py` / `compute_within_vs_between_slide_variance.py`
diagnostics were removed (not in paper v2.3; `mil-reframe` history). Promotion tooling:
`scripts/concat_cvae_history.py`. Tests: `tests/test_cvae_resume.py`. Configs:
`configs/exp_501.yaml` (corrected baseline), `configs/exp_601.yaml`–`exp_609.yaml`.

## 1. Motivation: diagnosing decoder collapse

This investigation was triggered by a finding from a CVAE counterfactual analysis
(decoding the same latent $z$ under both class labels): at the CVAE's original hyperparameters (β=2.0), the
decoder was found to reconstruct close to a near-constant per-class mean spectrum
regardless of the input's own latent code — a **posterior/decoder collapse**, not a
genuine per-instance effect. This was confirmed, not assumed, via three independent
diagnostics:

- **Within-class reconstruction spread**: the standard deviation of factual (own-true-
  class) reconstructions across different real instances of the same true class,
  measured at 0.1–16% of the real data's own within-class standard deviation.
- **Within-class correlation**: the correlation between a real spectrum's residual
  from its class mean and its own reconstruction's residual from the same class mean,
  measured at ≈0.33 (far below what a genuinely instance-sensitive decoder would show).
- **Synthetic-pool diversity ratio**: the same collapse, independently confirmed in the
  TSTR/TSRTR synthetic pools generated by the same decoder (3–31% of real data's
  within-class standard deviation).

A mode-collapsed decoder is expected to classify trivially well under any downstream
classifier precisely because it is reconstructing two well-separated, low-variance
class-mean attractors — this is why the probe's own flip-to-target-rate numbers,
taken alone, cannot distinguish "the CVAE learned a real per-instance counterfactual
effect" from "the CVAE collapsed." Resolving that ambiguity is the purpose of this β
sweep: locate a training regime where the decoder is demonstrably less collapsed,
before re-running any probe that depends on instance-sensitive reconstruction.

## 2. The CVAE objective and β's role

Per-batch training loss (`src/models/cvae.py::train_step`, one combined
`tape.gradient` call — every term shares the same backward pass):

$$\mathcal{L} = \mathcal{L}_{\text{recon}} + \beta \cdot \mathcal{L}_{\text{KL}} + \alpha \cdot \mathcal{L}_{\text{class}}$$

- $\mathcal{L}_{\text{recon}} = \gamma \cdot \text{MSE}(x, \hat{x}) + \delta \cdot \text{CosineDistance}(x, \hat{x})$
  (`reconstruction_loss_mode: "combined"`; every config in this sweep uses
  $\gamma{=}1.0, \delta{=}0.0$ — pure MSE).
- $\mathcal{L}_{\text{KL}} = -\tfrac12 \sum_j \big(1 + \log\sigma_j^2 - \mu_j^2 - \sigma_j^2\big)$,
  summed over the 32 latent dimensions, mean over the batch — the standard VAE closed-
  form KL divergence of $q(z|x)=\mathcal{N}(\mu,\sigma^2)$ against the prior
  $\mathcal{N}(0,I)$.
- $\mathcal{L}_{\text{class}}$: categorical cross-entropy of the encoder's auxiliary
  class head (`class_pred`) against the true label; $\alpha{=}0.2$, held fixed
  throughout this sweep (not itself the swept parameter).

**Mechanism linking β to collapse.** The decoder is conditioned on the true class
label directly (`Concatenate()([z, label])`), so it has two ways to minimize
reconstruction error: (a) use $z$ to reconstruct the instance-specific detail the
label alone cannot predict, or (b) ignore $z$ and reconstruct only the class-
conditional mean, which the label alone already determines. Path (b) is only
available to the optimizer if it can also drive $\mathcal{L}_{\text{KL}} \to 0$
(the posterior collapsing onto the prior, carrying no information about $x$) — and a
larger $\beta$ increases the gradient incentive to do exactly that, since it is
weighted more heavily than the reconstruction term it trades off against. This is
the standard $\beta$-VAE posterior-collapse mechanism; §1's collapse was observed at
this project's production value, $\beta{=}2.0$.

**Why KL is read as a diagnostic, not simply minimized.** $\mathcal{L}_{\text{KL}}$
is a genuine term in the minimized objective, so taken alone, a lower value is not
"better" in any absolute sense — but in this specific failure mode, $\mathcal{L}_{\text{KL}} \to 0$
is itself the collapse signature (the posterior degenerating to the prior, carrying
no per-instance information), so it is interpreted jointly with reconstruction loss:
a configuration with **both** lower reconstruction loss **and** a larger (non-
degenerate) KL term is read as less collapsed, not as "trading off worse" on the KL
axis alone.

## 3. Suite 600: flat β sweep (`exp_501` corrected, `exp_601`–`604`)

**Design.** Five flat (constant-throughout-training) β values: 2.0 (`exp_501`,
production baseline), 1.0, 1.25, 1.5, 1.75 (`exp_601`–`exp_604`). Every other
hyperparameter — encoder (`filters:[32,64,128]`, `kernels:[11,5,3]`,
`strides:[2,2,2]`), decoder (mirrored), `latent_dim:32`, `learning_rate:0.001`,
`batch_size:256`, `samples_per_class:20000`, $\alpha{=}0.2$, $\gamma{=}1.0,\delta{=}0.0$,
the 5-fold group-aware CV split, and the data preprocessing pipeline — is held
identical across all five configs, verified by a programmatic recursive dict-diff
against a shared base config before any GPU spend (not asserted by eye).

**Resume-from-checkpoint correction.** `exp_501`'s on-disk CVAE checkpoint predated
an epoch-count correction in its config (trained to only 70 of the now-specified 100
epochs, discovered via a direct `wc -l` check on its history CSVs, not assumed from
the config). Corrected via a new resume capability
(`_train_one_fold(..., resume_from_dir, epoch_offset)`, `pipeline/cvae_stage.py`):
loads existing per-fold encoder/decoder weights via `.load_weights()` before
`.compile()`, then continues training for the remaining epochs rather than
retraining from scratch; the Adam optimizer state is **not** restored (a fresh
optimizer at the resume point — a standard, documented caveat of this technique).
`epoch_offset` corrects only the epoch numbers written to the history CSV (and, where
active, the pre-existing linear-ramp annealing schedule's absolute-epoch reference);
it does not affect training itself.

**Evaluation metrics** (all computed per fold, then averaged over the 5 CV folds):
- Reconstruction (MSE) loss curve across training, read directly from each fold's
  `history_fold_N.csv`.
- KL loss curve across training, same source.
- **Synthetic/real per-feature standard-deviation ratio**, within class:
  $\text{ratio}_c = \overline{\sigma_{\text{synth}}(c)} \,/\, \overline{\sigma_{\text{real}}(c)}$,
  where $\sigma(\cdot)$ is computed per feature and averaged across the 571
  cropped-spectrum bands, $\sigma_{\text{real}}$ from that fold's real **training**
  split (the data the CVAE was fit to resemble), $\sigma_{\text{synth}}$ from that
  fold's generated synthetic pool, same class
  (`scripts/compute_synth_std_ratio.py`). A ratio of 1.0 means the synthetic pool
  exactly reproduces real within-class variance; well below 1.0 is the collapse
  signature quantified in §1.

All CVAE training in this sweep runs on a Modal T4 GPU
(`pipeline/modal_cvae.py::run_on_modal`); local CPU training was established earlier
in this project as impractically slow for this architecture/data scale. Every run is
preceded by a cheap smoke test (reduced epoch count) before committing to the full
GPU spend — a standing project practice, not specific to this sweep.

## 4. Windowed β-annealing follow-up (`exp_605`, `exp_606`)

**Motivation.** The flat sweep (§3) establishes a monotonic preference within
$\beta\in[1.0,1.75]$; this follow-up tests whether a **non-monotonic, alternating**
schedule built from values on both sides of 1.0 behaves differently from either a
flat continuation or the direction suggested by §3 alone, using the same total
additional training budget for a fair comparison.

**New config mechanism: `beta_window_schedule`.** Distinct from the project's
pre-existing linear-ramp annealing (`models.cvae.annealing`, a monotonic 0→max_beta
ramp over a configured warmup window, which cannot express an arbitrary alternating
step pattern). Schema:

```yaml
models.cvae.beta_window_schedule:
  window_size: 10      # epochs per window
  values: [1.25, 1.0, 1.25, 1.0, 1.25, 1.0, 1.25, 1.0, 1.0, 1.0]
```

Per epoch, `pipeline/cvae_stage.py::_train_one_fold` sets
`cvae.beta = values[min(epoch // window_size, len(values) - 1)]` (the final listed
value repeats if training runs longer than the schedule's own span); $\alpha$ stays
at its configured constant throughout. **Window indexing uses the local, 0-indexed
epoch counter of the current run, not the resumed/absolute epoch** — a deliberate
design choice, since a schedule is specified relative to "this training phase," not
the original model's absolute timeline; confirmed by a dedicated unit test
(`tests/test_cvae_resume.py::test_beta_window_schedule_windows_are_relative_to_this_run_not_epoch_offset`)
using a large non-zero `epoch_offset` and checking the recorded β trace is
unaffected by it. A second unit test
(`test_beta_window_schedule_applies_exact_per_window_values`) checks the recorded
`beta` column in the output history CSV against hand-computed expected values for a
small synthetic schedule.

**Design: three parallel branches from one shared ancestor.** All three variants
resume from the identical `exp_601` (flat β=1.0, 100-epoch) checkpoint
(`resume_tag` uploaded once to a Modal Volume, idempotent across the three
concurrent remote training calls), each training 100 further epochs
(`epoch_offset=100`, so each variant's own history reads as epochs 101–200):

1. **Constant-β continuation** (part of `exp_601` itself): β=1.0 flat, the control —
   isolates the effect of additional training time alone, holding β fixed.
2. **Schedule A** (`exp_605`): $\beta \in \{1.25,1,1.25,1,1.25,1,1.25,1,1,1\}$ per
   10-epoch window — mostly above 1.0.
3. **Schedule B** (`exp_606`): $\beta \in \{0.75,1,0.75,1,0.75,1,0.75,1,1,1\}$ per
   10-epoch window — mostly below 1.0.

**History-concatenation discipline.** A resumed run's own history CSV only covers
its own new epochs (101–200); promoting it onto the checkpoint it resumed from
requires merging with the original 1–100 rows, not overwriting them (an earlier,
explicitly logged incident in this project did exactly that — silently destroying
`exp_501`'s epoch 1–70 history). `scripts/concat_cvae_history.py` formalizes this:
reads both history CSVs, asserts the epoch ranges are contiguous with no overlap or
gap before writing anything, backs up any pre-existing file at the destination path
before overwriting it, and separately promotes the resumed run's (later-epoch)
weight files. Exercised with a dry-run mode and unit-level smoke tests (both the
plain-concatenation and promote-onto-existing-directory cases, plus the overlapping-
epoch refusal case) before being used on real training output.

## 5. Noise-floor decomposition for interpreting the std ratio

**Motivation.** §3's std-ratio diagnostic alone cannot distinguish "the shortfall
below 1.0 is mostly harmless, unstructured noise the CVAE has no reason to
reproduce" from "the shortfall is genuine, structured variation the model is failing
to capture." A reference point for how much of real within-class variance is
plausibly noise-like is needed.

**Method** (`scripts/compute_within_vs_between_slide_variance.py`): using the
existing slide/bag grouping already present in every fold's data (`train_groups`,
the same grouping used throughout this project's MIL machinery), real within-class
per-feature variance is decomposed via the law of total variance, using plug-in
sample moments (not a bias-corrected ANOVA estimator — a simplification consistent
with every other diagnostic ratio in this project):

$$\text{Var}_{\text{total}} = \text{Var}_{\text{within-slide}} + \text{Var}_{\text{between-slide}}$$

- $\text{Var}_{\text{within-slide}}$: the sample-count-weighted mean, across slides of
  the given class, of each slide's own per-feature variance.
- $\text{Var}_{\text{between-slide}}$: $\text{Var}_{\text{total}} - \text{Var}_{\text{within-slide}}$,
  clipped at 0.

Reported on the standard-deviation scale (for direct comparability with §3's std
ratio) as two fractions of $\sigma_{\text{total}}$; these do not sum to 1, since
standard deviations (unlike variances) are not additive.

**Interpretation caveat, stated explicitly.** This dataset contains no literal
repeated measurements of the same physical point, so within-slide spread is an
**upper bound** on pure instrument/measurement noise, not a clean estimate of it — it
still contains real intra-tumor cellular and spatial heterogeneity. It remains a
meaningful reference point for a different reason: the CVAE conditions generation
only on the class label, never on slide/patient identity, so it has no mechanism by
which to reproduce between-slide (patient-specific) structure regardless of training
quality — within-slide variance is the architecture-appropriate ceiling for what this
specific model could capture, not a claim about what fraction of real variance is
"unimportant."

## 6. Flat low-β extension with downstream evaluation (`exp_607`–`609`)

**Motivation.** §3's reconstruction/KL/std-ratio diagnostics establish a direction
(lower β reduces collapse) but not an optimum: a sufficiently low β risks reducing
the training objective toward a plain autoencoder with no effective distributional
regularization on $z$, which can produce a decoder that reconstructs its own training
instances well while leaving the sampling-time prior $z\sim\mathcal{N}(0,I)$ outside
the region the decoder actually learned to decode well (an aggregate-posterior
mismatch) — a risk invisible to any of §3's reconstruction-side diagnostics, which
never sample $z$ from the prior at all. Resolving this requires the actual downstream
task: classifiers trained on the generated synthetic pool, evaluated against
classifiers trained on real data.

**Design.** Flat (constant) β at 0.25, 0.5, 0.75 (`exp_607`/`608`/`609`), trained
from scratch (not resumed — these values were not part of any prior checkpoint's
history) for 120 epochs (longer than §3's 100, to give the lowest-β, furthest-from-
converged configurations more opportunity to plateau before being judged).

**Full pipeline, not CVAE-only.** Unlike §3–4 (`pipeline.stages: [cvae]` only),
these configs run `[trtr, cvae, tstr, tsrtr, stats_eval]`:
- **`trtr` is reused, not retrained**: `models_baseline_dir` points directly at
  `exp_501`'s existing trained classifiers. TRTR depends only on real data and fixed
  seeds, and every Suite 600 config's classifier hyperparameters
  (`random_forest`/`xgboost`/`cnn`/`apollo` blocks) and `cv_strategy` are verified
  byte-identical to `exp_501`'s — a fresh retrain would produce the same artifact, so
  `pipeline/run_suite.py`'s existing skip-if-outputs-exist check is relied on to
  avoid the redundant cost, rather than adding a separate code path.
- **`tstr`/`tsrtr`** train fresh classifiers on each config's own generated synthetic
  pool (TSTR) or a synthetic+real mix (TSRTR, `tsrtr.synth_ratio: 1.0`).
- **`stats_eval`** compares TRTR vs. TSTR ("can synthetic replace real training
  data?") and TRTR vs. TSRTR ("does synthetic augmentation improve on real-only
  training?") using this project's existing bag-level bootstrap comparison machinery
  — see docs/stage2_evaluation.md for that machinery's own methodology, unchanged
  here.
- **`mil_eval`/`mil_fit` are deliberately excluded.** Those stages belong to the
  separate, already-concluded MIL-tiers spatial-coherence investigation
  (docs/mil_tiers_findings.md) and are out of scope for this CVAE-tuning /
  TSTR-TSRTR comparison.
